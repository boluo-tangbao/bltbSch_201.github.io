# 店铺发现与账号核对流程

2026-10-18修订。每次研究分别完成“发现候选门店”和“核实门店营业／账号”，并记录各自进度。现成攻略只是起始名单，不能代表商场的全部门店。资料时效、默认展示与闭店处理遵守 [固定维护规则](shop-directory-rules.md)：2026年采用2025—2026年资料，当前官网目录实际核验后可用，过期来源归档。

旧报告中的构建／页面验收通过，只说明已接入内容可正常展示，不等于已满足本版的门店查找完成条件；后续研究按实际渠道与步骤判断进度。

## 1. 盘点范围与可复用证据

列出本轮城市、商场、馆区和已知相关楼层，沿用稳定`placeId`。从原店单、近期攻略、官网导览、既有照片门头及用户线索建立起始名单；照片日期或出处未知时只作待查线索。

复用之前实际读取的来源、账号和候选记录，注明原核对日期；没有新核实，不刷新`checkedAt`。本轮只读取与变更、过期或冲突有关的部分，不重新下载已有素材，不默认创建重放脚本。

## 2. 跨平台发现名单之外的店铺（必做）

小红书和抖音都要实际进行商圈范围的站内内容搜索；搜索引擎的`site:`结果不能代替站内搜索。另查可访问的商场／品牌官方目录或公告，记录是否取得有效资料。平台受限时记为“无法读取”，不能写成“已搜无结果”。

先用“城市＋商场／馆区＋谷店／吃谷”找近期内容，提取起始名单之外的店名。再针对缺口选择查询，不机械运行全部关键词与全部楼层的组合：

| 已发现的缺口 | 下一步查询 |
| --- | --- |
| 某馆区／相关楼层没有独立线索 | 商场＋馆名／楼层＋谷店；核对门头、地址或正文 |
| 只有总攻略、没有门店自己的内容 | 商场＋上新／补货／开业；从经营帖反查作者 |
| 搜索结果被餐饮、异地或同名品牌占据 | 加城市、C馆等馆区或“谷子／动漫周边”限定 |
| 已知店名可能不准确 | 简称、繁简体、英文名、门头写法；如“面包谷→面包谷谷” |
| 发现新名、搬迁或关店 | 沿新地址／旧名追查，先确认是否同一分店 |

内容结果用于发现门店及反查发布者；“用户”结果用于找账号，不能把两者混写为已完成。商场账号的提及、近期探店门头和经营帖中的新店名都进入候选表，不因它不在总攻略里而忽略。馆区／楼层没有搜到店时保留缺口，不推断该层没有谷店。

每次只记录实际执行的查询、结果模式、查看范围、有效来源链接、原文日期与新发现店名；建议查询单列，不能写成已执行。

## 3. 合并候选，逐店核实

先对齐正式名、简称、旧名、中英文／繁简体、城市、商场与铺位。同品牌不同分店分开记录；同一店改名保留别名，区域名、活动名、泛称及疑似重复项先待核，不为凑数当独立店铺。

每个候选都要有一次实际核实及处置记录：

1. 优先打开已发现的最匹配主页／官方目录，核对经营主体、城市和分店地址。全国品牌号需标为品牌号，异地分店及同名非商家排除。
2. 核对有效期内的本店经营内容，并检查闭店、搬迁、复业和主题结束冲突。当前官网门店目录也可确认营业，不强求另找社交号。
3. 没有匹配账号时，用正式名或一个有效别名做站内用户搜索；需要时从近期经营帖作者、商场提及或官网链接反查。小红书、抖音互补，不要求每店机械穷举所有平台。
4. 强候选一旦满足“主体匹配＋分店关联＋有效经营依据”，且没有未解决的关闭冲突，就保存证据并停止重复确认。账号身份可确认但缺营业依据时仍待核，不能为填满名单强行升级。

闭店公告优先于仍存在的账号及复用旧名单的较新攻略；恢复旧店展示需要复业依据。账号停用不等于实体闭店，线上上新不等于旧线下店营业，主题结束不等于零售店停业。春日百米店的关闭不能套到第一百货店，谷回线上仍经营不能抵消一百旧店关闭。

置顶、近期编辑或转载不能刷新原始事实日期；未标年份的月日保留原文，不推算。未标日期主页用于核对身份与当前地址，不能把读取日或注册日写为发帖日。新平台入口须先支持其类型和标签，不能把微博伪装成小红书。

不能猜主页URL、穷举用户ID、绕过登录／验证。首次打不开时记录失败，用已知有效入口或另一官方渠道补查；同一路径持续失败就列为受限，不循环重试。

## 4. 补漏、停止与交付条件

核对账号时另查门店／本期主题是否快闪、限时开放或有固定日期区间：把原始档期与适用范围写入`limited`，单列限时栏；账号仍活跃不能延长已结束主题。仅有每日营业时段、试营业、轮班表或促销日期时不据此判断限时，详见[固定维护规则](shop-directory-rules.md)。

先对比各渠道发现的名单，至少做一轮针对空白楼层、单一来源或新别名的补漏。该轮若又发现新店，核实新候选，并定向检查其暴露的缺口；不从头重跑已完成查询。

以下条件同时满足，才可写“本轮查找完成”：

- 小红书、抖音都做过商圈范围的内容发现，官方渠道已检查并记录结果。
- 馆区／已知相关楼层已检查；发现的空白、别名和来源差异已定向补查。
- 最近一轮补漏没有新增可归属本商圈的独立门店；仍出现新店就继续处理新增项。
- 全部候选已去重并有处置：确认营业、有效线索待核、闭店／过期归档、或关联不明暂不接入；已确认账号与闭店冲突均有原始依据。

平台受限、必要搜索未执行或候选未处理完时，可以交付已核实成果，但必须写“阶段性结果”，列出未完成项；不能仅靠列缺口就称覆盖检查完成。即使满足上述条件，也不宣称“全商场无遗漏”或给没有已知总数的名单计算覆盖百分比。

门店发现数量、营业确认数量、已确认账号门店数及账号入口数分别统计。一个共用号不当多个独立门店号，无账号不等于未营业。用户指出漏店时，记录漏在哪个渠道或步骤，用新线索补查同类缺口，不只补一行店名后声称名单完整。

## 5. 记录与节省重复工作

在 [城市研究工作单](templates/city-research.md) 中维护发现记录、候选及核实结果。最小记录包含：`placeId`、店名／别名、发现渠道／原始URL、实际查询与结果模式、核对日期、账号主页／名称／号／范围、地址依据、经营帖及原文日期、结果与原因、下一步。未取得字段用null，未执行和无法读取分开写。

节省重复读取与无效往返：合并独立查询，只提取相关门头、地址、日期和账号；复用原台账，一条可靠证据够用就停止追找同一事实。定稿后统一写入、校验和验收，只有新修改或失败才重跑相关检查。不得通过省略跨平台发现、逐店核实或补漏来节省额度。
