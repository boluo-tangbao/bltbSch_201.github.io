# B 站视频章节定位：Agent 执行说明

网站已接入商圈层级的 B 站视频片段入口，配置位于 `rank/src/data/bilibili-videos.json`，组件位于 `rank/src/components/BilibiliClips.vue`。默认不加载、不自动播放，减少访客无意产生的流量。

最新交互要求（优先于早期方案）：本站在加载前、加载后及关闭后都不展示具体视频标题、分 P、时间、“已选择”说明和“对应商圈视频片段”标题；单片段入口仅保留加载按钮与 B 站外链，多片段选择始终仅显示“片段 1／2”。具体来源与定位记录继续保存在配置及核查报告。第三方播放器内部自行显示的信息由 B 站控制。流量提示不常驻；点击加载时，仅当浏览器网络接口明确返回 `type: cellular`，才弹窗显示“加载后可能产生流量，点击播放器内的播放按钮开始观看。”，确认才创建／切换播放器。Wi-Fi、有线网络、未知或不支持网络类型接口时直接加载，不通过手机 UA、触摸屏或 `effectiveType` 的 3g／4g 速度标签猜测网络类型。取消不创建请求、不替换旧播放器。继续保留 `autoplay=0`、关闭播放器和 B 站外链。

2026-10-17 的商圈批量接入要求优先于下文早期方案：章节只作为查找范围，每个商圈必须单独核实正式介绍起点，保留完整开句与必要引入，不能给同章所有商圈套用章节起点。配置保存核查方式、具体依据、复查链接；实际引入早于章节标记时，必须填写 `chapterOverlapNote` 解释。证据不足的记录为 `pending`，不填估算时间、不启用播放器。商圈入口位于 `PlaceDetail.vue` 的介绍区块之后，不放入 `ShopDirectory.vue` 的各店铺卡片。

本次真实视频、10 个章节和 17 处接入的逐项结果见 [BV1uUWizfEvv 核查报告](research/bilibili-BV1uUWizfEvv/report.md)。

广州补充视频的 6 个章节、5 处接入及完整引入复查见 [BV1EFfJBwEjh 核查报告](research/bilibili-BV1EFfJBwEjh/report.md)（2026-10-20）。

苏州 `BV1Ykho6fEKd` 公开接口确认无作者章节，3处商圈的独立视频定位与验收并入[原苏州报告](research/suzhou-review-20261019/report.md#苏州视频引用补充2026-10-20)。无章节时，整段视频入口仍默认0秒；按上方逐商圈核实要求，确已独立核对完整开句的商圈片段可填写 `startSource: "independent-review"`、核查方式、依据及复查链接，保留 `chapterStatus: "none"`、空 `chapters`，不虚构作者章节。未完成核查的片段仍为 `pending`，不填写估算时间；读取失败也不能通过该标记启用播放器。

## 可直接交给 Agent 的 Prompt

请依据 `docs/bilibili-chapters.md` 和下方批量清单，为本网站批量实现、配置 B 站视频章节入口。先读取仓库规则与目标页面实现，复用现有样式和内容数据结构。由你从给定 B 站视频读取真实标题、章节名称、时间和分 P，用户不需要手工列章节，也不提供封面。根据“接入位置”匹配网站已有条目和视频章节；匹配唯一明确的直接执行，有歧义或读取失败的集中报告，继续完成其余条目。遵守下述交互与验收要求，不顺带改版，不推送、不发布，除非用户另有授权。已正确配置的条目跳过，新增或变更条目更新，避免重复入口。不要把虚构视频、时间或开发示例放入公开页面。

## 用户填写的批量清单

每个视频填写一个块；复制下面的块即可批量增加。只需提供视频链接与接入位置，章节由 Agent 读取，封面不使用。

```text
### 视频 1
视频链接：https://www.bilibili.com/video/这里替换为真实BV号/
接入位置：
- 网站栏目：逛店榜单；内容条目：上海 / 店铺甲；展示位置：详情文字之后；章节选择：自动匹配该店铺对应章节。
- 网站栏目：逛店榜单；内容条目：上海 / 店铺乙；展示位置：详情文字之后；章节选择：自动匹配该店铺对应章节。

### 视频 2
视频链接：填写真实链接
接入位置：
- 网站栏目：活动记录；内容条目：填写活动名称和日期；展示位置：相册介绍之后；章节选择：展示全部章节，默认第一章。
```

上面名称仅为填写示例，不是实际接入任务。执行时以用户提供的真实清单为准。

### “接入位置”怎么填

- **网站栏目**：写你在网站看到的栏目名，如“逛店榜单”“活动记录”；知道页面路径也可以直接写路径，不要求了解源码。
- **内容条目**：店铺写“城市 / 店名”，活动写“日期 / 活动名”；也可直接提供对应详情链接或已有稳定 ID。Agent 负责定位实际文件和 ID，不凭同名猜测。
- **展示位置**：写“详情文字之后”“相册介绍之后”等可见位置；省略时放在该条目的介绍文字之后，避免放进列表卡片导致重复展示。
- **章节选择**：通常写“自动匹配该条目对应章节”；需要整段视频时写“展示全部章节，默认第一章”；也可只写 B 站上已有的章节名称，无需填写时间。一个条目对应多章时保留相关章节，默认最早一章。

例如，你可以只写：“视频链接：……；接入位置：逛店榜单中上海的店铺甲、店铺乙详情文字之后，各自匹配对应章节。”Agent 应将这句话转换为配置，无需要求用户提供源码路径。

## Agent 读取章节与批量匹配规则

1. 在维护阶段使用可用的浏览工具或经验证的公开数据接口，读取视频页面已公开的标题、章节、时间和分 P；不要假定 iframe 参数文档提供章节读取接口。必要时查看页面中已公开的简介时间目录，记录其实际来源。
2. 将读取结果保存到仓库的内容数据中，并记录视频来源链接和读取日期。网站访客只读取本站静态配置，不在打开页面时调用 B 站接口取章节。
3. 按条目名称、城市或活动上下文与章节标题匹配。唯一明确的匹配直接执行；同名、多义或章节范围不清楚时，保留原配置，将该项列为待确认，不随意选择。
4. 区分“确认没有章节”和“章节读取失败”。确认无章节时默认使用整段视频、从 0 秒开始，并报告该结果；独立核实的商圈片段按上方 `independent-review` 规则记录。读取失败时不要伪装成无章节，跳过该项并说明阻塞原因。确实需要补充信息时再集中请求章节文字或时间，不将手工列章节作为默认要求。
5. 不读取私人 Cookie，不索要账号密码，不绕过访问限制。只保存章节元数据，不下载视频或封面。
6. 交付时按接入条目汇总：视频、实际页面或条目 ID、匹配章节及时间、处理结果、待确认原因，便于批量核对。

## 交互要求

1. 页面初次打开、滚动到视频、展开详情、URL 带章节参数时，均只显示加载入口和必要的片段选择，不展示具体出处、时间或封面。不要创建 B 站 iframe，不发起 B 站封面/API 请求，不预连接或预加载 B 站资源。单靠 `loading="lazy"` 不满足要求。
2. 点击片段仅更新待选状态；选择项使用“片段 1／2”，不展示具体标题、分 P 或时间。此操作不加载播放器、不开始播放。条目入口默认选中已匹配的片段，完整视频入口默认第一章；确认无章节时从 0 秒开始。
3. 用户明确点击“加载此片段播放器”后才创建 iframe，将所选秒数写入 `t`，始终设置 `autoplay=0`。已识别的蜂窝网络需先确认流量弹窗，Wi-Fi 或网络类型不可识别时不弹窗；不常驻流量提示。加载操作本身也不要自动播放。
4. 播放器内部由用户点击播放。不要使用自动播放权限、模拟点击、脚本或其他方式绕过用户操作。
5. 播放器已加载时，选择另一章仍只更新待选状态；提示“点击加载按钮切换到所选章节”。再次明确加载时替换旧 iframe，传入新时间并保持 `autoplay=0`。不同时保留多个播放器。切换分 P 也遵循相同规则。
6. 提供“关闭播放器”入口，移除 iframe，保留章节选择。关闭弹窗或离开对应详情时也移除 iframe，终止旧播放器继续工作。
7. 保留“去 B 站观看”原视频链接，播放器不可用时仍能访问。不要声称已经播放成功；跨域 iframe 的 load 事件只能说明框架页面加载。
8. 手机和桌面均可用，按钮支持键盘操作、选中状态可感知；播放器带明确的 `title`，保持合适画面比例，不横向溢出。加载前使用紧凑的文字区域，不预留大片封面占位。加载后第三方播放器自身呈现的画面由 B 站控制。

## 配置数据

将数据放入适合目标页面的现有内容结构；字段命名可以随项目惯例调整，但必须保留下面的含义。一个视频可关联多个内容条目，每个条目可指定默认章节；不要为每章复制完整的视频配置。

以下是 Agent 生成的内部配置结构示意，不是用户要填写的表单。`bvid`、标题和章节必须替换为从真实视频核实的内容，示例不可进入公开页面：

```json
{
  "id": "my-vlog",
  "title": "视频标题（待填写）",
  "bvid": "待填写真实 BV 号",
  "chapters": [
    { "id": "intro", "title": "开场（示例）", "startSeconds": 0, "page": 1 },
    { "id": "visit", "title": "逛店实拍（示例）", "startSeconds": 135, "page": 1 }
  ]
}
```

- `startSeconds` 为从该分 P 开头计算的非负整数秒，`page` 为从 1 开始的分 P 编号，默认 1。普通时间章节不等于分 P。
- 由 Agent 将读取到的章节时间转换为秒数，显示时再格式化。校验时间、BV 号、章节 ID 唯一性；同一分 P 的章节按时间升序排列，不擅自编造时间。更新时保持已有稳定 ID；来源章节删除或匹配关系变化时明确报告，不默默指向另一章。
- 不设置封面字段，不下载、抓取或要求用户提供封面。
- 原视频链接由合法 BV 号生成，避免任意 HTML、iframe 或不受控 URL 注入。
- 章节由 Agent 在维护阶段读取并保存。区分视频元数据与接入关系：视频配置保存章节，页面或内容条目通过视频 ID、相关章节 ID 和默认章节 ID 引用，避免重复维护。

## 播放器实现依据与边界

B 站官方文档：<https://player.bilibili.com/>，于 2026-10-17 核对。官方支持 `bvid`、`p`、`t`（初始秒数）、`autoplay` 等参数，实施时可再次核对。

构建地址示意：

```text
https://player.bilibili.com/player.html?bvid=<真实BV号>&p=1&t=135&autoplay=0
```

使用 `URL` / `URLSearchParams` 构建地址，播放器域名固定为 `https://player.bilibili.com`。支持全屏；iframe 的权限只按实际需要添加，不授予 autoplay。

跨域限制下不能直接操作 B 站 iframe 内部 DOM 或其 video.currentTime。除非有已验证的官方控制协议，否则通过用户明确加载后重建 iframe 来切换初始时间。不要承诺无缝跳转或自行设计 postMessage 协议。

`autoplay=0` 表示请求关闭自动播放，不能保证第三方播放器完全不缓存视频；“不加载播放器前不请求 B 站资源”才是本站能控制并验证的省流边界。真实视频的时间定位、登录要求、可播放性及移动端表现必须实际验证；遇到第三方行为差异应据实记录，并保留关闭和外链入口。

## 验收要求

- 首次进入及仅选择章节后，网络面板中无该功能触发的 B 站请求，DOM 中无 B 站 iframe。
- 明确加载后只有一个 iframe，其参数与当前章节一致，`autoplay=0`，视频不自行播放；实际播放从所选时间附近开始，以播放器行为为准。
- 已加载后选章不会改写 iframe；再次加载后旧 iframe 被移除，新章节仍等待手动播放。
- 关闭后 iframe 被移除；重新打开、返回详情或按章节链接进入不会恢复自动加载。
- 验证无章节、章节读取失败、匹配歧义、重复执行、非法配置、普通时间章节及分 P；非法配置显示可理解的状态，不构造错误播放器。确认没有封面字段和该功能发起的封面请求。
- 桌面、窄屏和键盘操作可用，原站链接可访问。使用真实视频完成浏览器验证；若缺真实配置，只报告已验证的组件行为，不声称完成真实 B 站播放验证。
- 运行与修改范围相称的项目检查。交付时列出配置文件位置、填写示例、已完成的验证及第三方限制。

涉及店铺一览或其来源数据时，继续遵守 `docs/shop-directory-rules.md`，本方案不改变店铺维护规则。
