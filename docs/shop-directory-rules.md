# 店铺一览固定维护规则

本规则按用户于 2026-10-18 至 2026-10-20 的要求修订，适用于之后所有店单更新，优先于早期研究记录中的旧要求。

## 常规谷店依据展示（2026-10-20补充）

按本次用户要求，常规谷店以卡片是否展示已核对的小红书／抖音账号决定依据展示：有账号时隐藏文字“依据说明”、营业／位置来源与主营依据列表；无账号时保留原文字说明，并显示全部对应出处链接，即使该店已通过官方店单确认营业也适用。默认折叠的无账号线索同样保留说明和链接。原始 `note`、`sources`、`kindSources` 数据全部保留，只改变显示。限时谷店／快闪沿用现有规则：说明保留，营业中隐藏两类来源列表、待核实显示。常规谷店不显示“作者到访记录”；限时条目按原规则保留该标注。位置附在店名旁，以小字显示，过长自然换行，不再单列“位置”字段；主营、账号入口及营业分类不变。

同一出处URL在营业／位置与主营依据中重复出现时，页面合并为一个链接并标注支持范围；不同标题、原日期和独立来源保留。仅支持主营的链接明确“不作为当前营业确认”。原始数据不去重删除。

常规与限时两栏的确认店铺各默认展示前5家，标题旁“展开全部”按钮每次只增加5家，余数不足5家时全部补出；待核实区保持默认折叠，展开后也先显示5家、每次增加5家。计数仍显示全部有效店单数量；刷新或切换地点重置。搜索定位到后续店铺时自动展开到包含该店的5家批次，不把已确认店铺误放入待核实区。

## 限时店铺单独分栏（2026-10-18补充）

- 快闪、慢闪、明确限时开放、具有固定开放日期区间的门店或本期限时主题，必须单列“限时谷店／快闪”，不混入“常规谷店”。营业确认与限时属性分别判断，不能因为已找到账号就把快闪当常规门店。两栏均默认展示确认营业条目，待核实项分别置于各自默认折叠的“展开更多”；闭店、已结束主题两栏都隐藏。
- 填写 `limited: { scope, period, startsOn?, endsOn? }`。`scope: "store"`表示整家临时门店，`"theme"`表示这一期主题；`period`必填。来源明确完整年月日，或按用户2026-10-19确认的平台日期规则结合发表时间及正文上下文可靠判断年份时，可填`startsOn/endsOn`（YYYY-MM-DD），允许只知道一端；归档原文和推断理由。正文跨年、回顾旧事或年份仍不明时仅填原文档期。已明确限时但档期不明时写“档期待公布／待核实”，仍分到限时栏。
- 促销活动、商品首发日期、每日10:00—22:00等常规营业时段、试营业和当值排班表本身，不构成门店限时依据。普通店不能只因介绍里出现旧快闪／联动就迁入限时栏；需核对本条记录的对象。常设店本期限时主题用`scope: "theme"`并标明主题名，主题结束隐藏这一期记录，不据此宣布整店关闭，也不将同一主题／铺位重复计店。
- 每次内容复核检查档期。结束日早于该店单`checkedAt`的已知日期条目必须改为`status: "closed"`，保留原始来源和限时字段；校验器会拒绝仍展示的已结束记录。当前页面不依赖关键词猜分类，也没有按访问当天自动下架功能；不能仅推进`checkedAt`却不处理过期主题。仅做分栏／格式整理不刷新营业核对日期。
- 卡片在主营之后增加“开放期／主题期”。验收分别统计常规确认、限时确认、两栏待核实及归档；页面总数为前四项之和。检查两栏各自默认折叠、闭店隐藏、按下文账号与分栏规则显示依据、待核实原始链接保留，分类与档期依据可追溯。

## 营业与来源维护

- 信息窗口为当前年度和上一年度：本轮采用2025-01-01至2026-10-18资料，后续随年份推进。2025年以前的帖子不作为本轮营业、位置、主营或补图依据；旧来源仅保留在研究归档。未标日期的当前官网门店目录可在实际读取后作为例外，记录读取日期，不把读取日期伪装成发布日期。置顶旧帖、搜索抓取日期、近期转载旧文均不能刷新原始资料时效。
- 店铺查找与账号收集必须执行 [店铺发现与账号核对流程](shop-account-research.md)：先通过小红书、抖音的商圈内容搜索发现攻略之外的新店，再逐店核实账号、地址和营业依据，按楼层及渠道差异补漏。分别记录发现进度和核实进度；渠道受限、必要步骤未完成时标为阶段性结果。不能把只核对既有名单写成查找完成，也不能把搜索结果页当账号主页。停止条件与节省重复工作的办法见该流程。

- 默认展示已确认营业、显示为“营业中”的店铺。确认依据包括已核对的小红书／抖音官方账号，以及官方店单／官网明确列出该门店仍在营业。后者填写 `operatingConfirmation: "official-listing"`，不要求另有社交账号；仅有历史报道或品牌品类说明不能自动添加该字段。用户于 2026-10-07 明确确认动漫星城的 animate、BUSHIROAD、GOODSFUN 属于官方店单确认营业的情况，本轮据此设置。账号必须确实关联对应门店，品牌账号需注明品牌号，不能将其他城市或同名账号当成当前门店证据。
- 没有确认营业、但有近两年有效线索的条目放入默认折叠的“展开更多”，标为“有营业线索”。明确闭店或已结束的主题店不在页面展示，也不计入展开数量；原始数据／研究归档保留闭店依据，供去重和避免误恢复。闭店公告优先于已有官方账号，不能因账号仍存在恢复为营业中。
- 近期发表不等于阵容近期核实。攻略可能重复旧店单；逐店检索闭店／更名／搬迁后再接入。较新攻略仍列旧店名，不能覆盖明确闭店公告或官方更名；恢复展示需要重新营业依据。闭店清仓公告可支持“已公布闭店”，不能据此补造实际撤店日期。
- 官方账号不是唯一值得保留的依据。小红书探店、抖音帖子、商场报道、楼层攻略、作者照片与官网资料等，继续保存原始链接、来源名称、时间和说明。常规谷店有账号时隐藏文字说明和两类来源列表、保留官方账号入口；无账号时，无论官方店单确认营业还是折叠线索，均保留文字说明及来源链接。限时栏沿用营业中隐藏来源列表、待核实展示的规则。过期资料不在生产卡片中兜底，移入研究归档，不能丢失原文。
- 折叠区的主营证据 `kindSources` 与其他出处按URL合并展示；仅支持主营的来源标注“不作为当前营业确认”；商品介绍或旧探店不能自动升级营业状态。存在新旧冲突时在 `note` 解释各条证据的适用时间与范围。
- 使用真实 `date` 或原始 `dateLabel`，不将核对日期写成发帖日期，不补造具体日期。没有新核实，不更新 `checkedAt`；页面布局改动不等于营业复核。
- 2026-10-19日期解释补充：小红书／抖音发表日期省略年份、仅显示月日，按实际读取当年解释，可将补足后的发表日写入`date`，原标签及理由存研究台账；不是将读取日当发表日。只有编辑日期则用`dateLabel`明确“编辑时间”，不伪装原发表时间。正文月日与发表时间、明确年份及上下文对照后可补足活动年份；可靠旧研究的本分店经营线索应复用、提高相应事实证据强度，但不能冒充官方确认或抵消明确闭店。
- 更新数据的位置：`rank/src/data/shop-directories.json`。展示入口：`rank/src/components/ShopDirectory.vue`；营业展示分类：`rank/src/utils/shopDirectory.ts`。
- 维护已有店单先核对原记录是否对应本分店，复用原来源与读取日；仅补查新候选、失效来源、关闭／迁址／档期冲突及明确缺口。研究与页面复验直接更新原商圈报告，来源的唯一信息保留一次即可，按[归档与清理规则](city-expansion-workflow.md#归档与清理)移除重复副本、临时脚本及已被替代的验收产物。
- 卡片顺序固定为：店名（旁附小字位置）与状态 → 主营 → 开放期／主题期（限时条目）→ 线索时间／作者到访（作者到访仅限时条目）→ 依据说明 → 合并去重的出处链接及适用范围 → 官方账号；缺少字段时省略，不猜填。
- 主营统一写简短品类，用顿号分隔，不混用“与／及／等”连接词；动漫和游戏合并范围写“动漫／游戏周边”，模玩统一写“模型”。已确认的作品、品牌、合作方放括号补充，保留寄售、中古、联动、限时快闪等实际区别，不把“含某作品”改成专营。楼层统一写“一层／二层／三层／负一层”等；LG 保留商场标识，不推断楼层。来源标题、原始链接、证据日期与必要的搬迁／闭店／活动说明保留原意。
- 修改后运行数据校验和构建，验证折叠区初始关闭、可点击展开；页面数量＝确认营业＋有效待核实，闭店数量为零，归档数量另列。常规有账号不显示文字依据与两类来源列表，常规无账号必须显示文字说明及有效出处链接；限时栏按原规则显示。来源筛选、账号核对和旧名合并须在研究报告中可追溯。
