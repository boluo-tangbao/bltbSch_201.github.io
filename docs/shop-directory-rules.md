# 店铺一览固定维护规则

用户于 2026-10-07 确认，本规则适用于之后所有店单更新，优先于早期研究记录中“全部直接展示”或“不渲染证据链接”的历史要求。

- 默认展示已确认营业、显示为“营业中”的店铺。沿用当前已核对小红书／抖音官方账号的口径；账号必须确实关联对应门店，品牌账号需注明品牌号，不能将其他城市或同名账号当成当前门店证据。
- 没有确认营业的条目放入默认折叠的“展开更多”，标为“有营业线索”；明确闭店的记录也放在折叠区，保留“已公布闭店”。闭店公告优先于已有官方账号，不能因账号仍存在恢复为营业中。
- 官方账号不是唯一值得保留的依据。小红书探店、抖音帖子、商场报道、楼层攻略、作者照片与官网资料等，继续保存原始链接、来源名称、时间和说明。页面展示 `note`、`sources`，保留官方账号入口；不得因折叠或新来源而删除旧依据。
- 主营证据 `kindSources` 单独展示并说明“不作为当前营业确认”；商品介绍或旧探店不能自动升级营业状态。存在新旧冲突时在 `note` 解释各条证据的适用时间与范围。
- 使用真实 `date` 或原始 `dateLabel`，不将核对日期写成发帖日期，不补造具体日期。没有新核实，不更新 `checkedAt`；页面布局改动不等于营业复核。
- 更新数据的位置：`rank/src/data/shop-directories.json`。展示入口：`rank/src/components/ShopDirectory.vue`；营业展示分类：`rank/src/utils/shopDirectory.ts`。
- 卡片顺序固定为：店名与状态 → 位置 → 主营 → 来源时间／作者到访 → 依据说明 → 营业／位置来源 → 主营来源 → 官方账号；缺少字段时省略，不猜填。
- 主营统一写简短品类，用顿号分隔，不混用“与／及／等”连接词；动漫和游戏合并范围写“动漫／游戏周边”，模玩统一写“模型”。已确认的作品、品牌、合作方放括号补充，保留寄售、中古、联动、限时快闪等实际区别，不把“含某作品”改成专营。楼层统一写“一层／二层／三层／负一层”等；LG 保留商场标识，不推断楼层。来源标题、原始链接、证据日期与必要的搬迁／闭店／活动说明保留原意。
- 修改后运行数据校验和构建，验证折叠区初始关闭、可点击展开，确认店铺总数没有丢失、闭店不误入默认列表、原始证据链接仍可见。
