## 停止营业历史（2026-10-24用户要求）

用户要求将原来营业、现因闭店或装修可能停止营业的店铺单列“停止营业”，保留营业历史和原位置；分类按用户进一步明确的口径：“已停止营业”仅指彻底关店，或迁往其他地点（不含同一商场换楼层）的旧店；因装修暂时关闭、表示会继续开但尚未恢复的标“装修停业”；同一商场换楼层且新址营业已核实者继续按新位置展示。本节是下文“闭店隐藏”规则的显式例外，优先适用。适用于后续所有商圈的增量维护；已有历史逐条核对证据后接入，不批量恢复其他商圈的旧店、已结束主题或迁出记录。

- 需展示的历史条目仍设 `status: "closed"`，另填 `inactive: { reason, history }`；`reason`仅为`closed`（彻底关店，显示已停止营业）、`relocated`（迁往其他地点的旧店，显示已停止营业并在说明中注明去向）、`renovation`（装修停业）、`unconfirmed`（停业待核实）。`history`保存有依据的经营／停止时间原文，位置沿用`floor`，前台标“原位置”。不补造开业日、停业日；用户反馈日不能当作实际停业日。
- 营业历史可写“～2026.10.1”或起止区间，但日期必须有明确依据；只知道最后一次经营记录时写“2025-07-27有经营记录；停止时间待核”，不能将它当停业截止日。开业日、撤店日、迁址日与公告／编辑／用户反馈日分开记录；无法确定的端点保留未知。`floor`只存原楼层／铺位值，不重复写“原位置”前缀，去向放说明并附链接。
- 装修停业须有装修或暂时关闭并计划继续经营的依据；如面包谷谷“会继续开”的装修公告，不据此认定彻底闭店。停止原因或旧址是否保留仍不清楚时用`unconfirmed`，明确写“停业待核实”；仅因暂未搜到账号、账号停更、同名号为空或某层店铺减少，不能推定闭店。
- 停止营业单列计数，不计入常规／限时确认或待核实；先展示5条，每次展开5条，刷新复位。无明确营业历史、仅有失效旧名单的条目仍只归档，不虚构在营历史。
- 即使保留原小红书／抖音账号，停止营业卡片也显示文字说明、合并后的全部出处及“原账号”；账号存在不抵消停业冲突。同一商场内换楼层且新址经营已核实者移除`inactive`，按新位置在当前店单保留，不重复计入停止营业。迁往其他地点的旧店可使用`reason: "relocated"`记录已停止营业历史，在说明与来源中注明去向；新地点的店继续独立按其经营依据维护，不因此认定整个品牌停业。尚未确认去向时不猜填外迁。
- 主题到期只结束这一期记录，不使用`inactive`宣布整店停业；未选入停止营业历史的closed记录继续隐藏。原始来源、原日期、旧账号保留，历史展示不把旧来源刷新为当前营业依据。
