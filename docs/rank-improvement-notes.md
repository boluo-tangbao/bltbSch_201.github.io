# 逛店体验榜后续优化备忘录

根据当前网站和数据整理，优先推进以下三项。目标是让读者理解排名依据、看到支撑评价的现场信息，并判断内容是否仍然适用。

## 1. 讲清楚排名依据

目前榜单有五档推荐度和档内顺序，但“关于这份榜单”仍写着“其余评价标准待补充”。建议先用作者自己的话补充判断方式，无需把主观体验硬算成分数。

- 说明排名对象：单店、商场和街区是否放在同一榜单比较；若放在一起，依据是什么。
- 说明主要考虑的因素，例如谷店密度与品类、价格与淘货体验、活动、交通、逛店舒适度。明确哪些因素对自己更重要。
- 说明档位含义和同档排序：什么地方值得专程去，什么地方适合顺路逛；同档为什么还要分先后。
- 在具体条目里写出决定档位的关键理由，尤其是读者可能有不同看法的条目。保留个人口吻，不要求每家都套同一模板。

可先修改 `rank/src/data/site.json` 中的 `criteria` 和 `tierDescriptions`，再逐步补充 `rank/src/data/places.json` 中各条目的 `details`。

**完成标志：**第一次打开网站的人，不看原视频也能理解五档的区别，以及一处地点为什么被放在当前档位。

## 2. 用精选照片支撑评价，并减轻图片负担

目前 25 个公开条目的 `gallery` 均为空，详情页也尚未展示图集；仓库的地点图片目录约 1 GB，25 张封面合计约 22.5 MB。图片文件进入部署产物，但访客不会一次下载整个目录。仍值得先处理较大的封面，并清理未使用素材。

- 每个重点条目精选 2～4 张能说明评价的照片，例如店面、主要品类、动线或活动现场；为照片写简短说明和拍摄日期。避免单纯堆图。
- 给详情页增加图集展示，再把选好的图片写入条目的 `gallery`。目前只填写数据还不足以在详情页看到图集。
- 将榜单封面单独压缩成适合卡片展示的尺寸；需要细看的原图再从详情页按需加载。优先处理数 MB 的封面。
- 核对公开素材的来源与使用权限，移除不再使用的原图、视频和重复文件，保留必要的原件备份。

**完成标志：**重点条目能通过少量现场照片说明“为什么这么评”；手机打开榜单时，封面加载更轻快。

## 3. 让更新记录反映信息时效

当前 25 条更新记录都是“首次加入榜单”，说明了收录时间，但还不能帮助读者判断店铺近况。后续重点记录有实际参考价值的变化。

- 重访后更新评价时，记录重访日期、观察到的变化和结论是否改变。
- 升档、降档时写明原因，例如店铺阵容、价格、活动或个人体验发生了什么变化。
- 搬迁、停业、装修、活动结束等易过时信息，优先标出状态与核实日期；尚未确认时如实写“待核实”。
- 更新记录只保留对读者有意义的变化，普通错字修正无需占用“最近更新”的位置。

主要维护 `rank/src/data/places.json` 的到访日期、内容更新日期与评价，以及 `rank/src/data/updates.json` 的变更类型和原因。

**完成标志：**读者能从条目和更新记录看出“什么时候去过、什么时候改过、为什么改”，并据此判断信息是否适合这次出行参考。

## 建议顺序

1. 先写清榜单依据和五档标准。
2. 选几处代表性地点试做“评价 + 精选照片”，确定适合长期维护的格式。
3. 从下一次重访开始认真记录变化；等格式稳定后再批量整理旧素材。
